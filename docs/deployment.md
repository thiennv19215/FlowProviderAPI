# Production deployment on a VPS with Cloudflare Tunnel

This deployment keeps the FlowProvider origin private. The VPS runs PostgreSQL, the API, and `cloudflared` in one Docker Compose project. Cloudflare terminates public HTTPS and forwards the published hostname through an outbound-only Tunnel to `http://api:8000` on the private Docker network.

The Chrome extension remains on a Chrome machine signed in to Google Flow. It connects to the public Provider hostname over WSS; Chrome and Google Flow do not need to run on the VPS.

## Architecture

```text
API clients / Chrome extension
            |
        HTTPS / WSS
            |
        Cloudflare
            |
     Cloudflare Tunnel
            |
          VPS
     +------+------+ 
     |             |
 cloudflared      API
                  / \
        PostgreSQL   local assets volume
                     (reference uploads)
```

The production Compose file publishes no API or PostgreSQL host ports. `cloudflared` reaches the API by Docker DNS at `http://api:8000`. Generated Flow image and video bytes are not stored on the VPS: successful tasks expose the direct Provider URL. The local assets volume only persists user-supplied reference uploads and fallback media that has no Provider URL.

## 1. VPS prerequisites

Use a supported Linux VPS with Docker Engine and the Docker Compose plugin installed. Clone the repository and stay on the production revision you intend to deploy:

```bash
git clone https://github.com/thiennv19215/FlowProviderAPI.git
cd FlowProviderAPI
git checkout main
```

Because Cloudflare Tunnel is outbound-only, the Provider does not need inbound ports 80, 443, 8000, or 5432. Keep only the administration access you actually use, for example SSH.

If the VPS uses an outbound firewall, allow `cloudflared` to reach Cloudflare. Cloudflare documents port 7844 as the tunnel connectivity port.

## 2. Create the production environment

```bash
cp .env.production.example .env.production
chmod 600 .env.production
```

Generate separate secrets. Hex values avoid URL-encoding surprises in the PostgreSQL connection string generated by Compose:

```bash
openssl rand -hex 32
printf 'fpa_prod_'; openssl rand -hex 32
```

Use them for, respectively:

- `POSTGRES_PASSWORD`
- `FLOW_PROVIDER_BOOTSTRAP_API_KEY` on the first deployment (client bootstrap only)
- `FLOW_PROVIDER_ADMIN_API_KEY` for the deployed administration dashboard

Do not reuse the same value for multiple credentials. The production Compose
configuration requires `FLOW_PROVIDER_ADMIN_API_KEY`; deployment stops during
configuration validation when it is empty or missing.

Set `FLOW_PROVIDER_PUBLIC_BASE_URL` to the final HTTPS hostname, for example:

```env
FLOW_PROVIDER_PUBLIC_BASE_URL=https://provider.example.com
```

Production startup intentionally fails unless PostgreSQL, HTTPS, and durable reference-upload storage are configured.

### Bootstrap API key

`FLOW_PROVIDER_BOOTSTRAP_API_KEY` creates a normal API client if that key does not already exist. Keep the generated key in a password manager. After the client has been persisted in PostgreSQL, the environment value may be cleared on later deployments; the database client remains. Provider administration is separate: configure `FLOW_PROVIDER_ADMIN_API_KEY` and send it in the `X-Admin-Key` header for control-plane endpoints.

### Administration dashboard

The dashboard is bundled into the API image and is deployed at:

```text
https://provider.example.com/admin
```

Enter the configured `FLOW_PROVIDER_ADMIN_API_KEY` when prompted. The browser
keeps it only in the current tab's JavaScript memory; refreshing or closing the
tab requires entering it again. The plaintext key is never sent to the API
except in the `X-Admin-Key` header.

## 3. Configure reference-upload storage

The default production configuration keeps user-supplied reference uploads in the Docker named volume mounted at `/app/.data/assets`:

```env
FLOW_PROVIDER_LOCAL_STORAGE_PATH=/app/.data/assets
```

Generated Google Flow outputs are not copied into this volume. Their compact string `media_id`, internal Flow media mapping, and direct output URL are registered in PostgreSQL. The direct URL can be returned immediately to the calling backend.

Direct Flow output URLs remain upstream-owned and may expire or be revoked. An integrating backend that requires permanent output media should download each successful result promptly into its own storage.

Do not commit `.env.production`. The repository ignores production env files and local backup dumps.

## 4. Create the Cloudflare Tunnel

Create a remotely-managed Cloudflare Tunnel in the Cloudflare dashboard. Copy the tunnel token into:

```env
CLOUDFLARE_TUNNEL_TOKEN=...
```

Add a published application route:

```text
Public hostname: provider.example.com
Service:         http://api:8000
```

`api` is the Docker Compose service name. `cloudflared` runs in the same Compose network, so it can resolve that name without exposing port 8000 on the VPS.

Cloudflare creates/routes the hostname to the Tunnel. The origin itself stays private.

### Cloudflare rules for the Provider hostname

Treat this hostname as an API/WebSocket origin:

- do not add a Cache Everything rule for it;
- do not put an interactive browser challenge in front of API or WebSocket requests;
- if Cloudflare Access is enabled, clients and the Chrome extension need a non-interactive service-token flow, which FlowProvider does not currently inject automatically;
- keep normal WAF/DDoS protections;
- if a valid API request is blocked with Cloudflare error `1010`, open its Ray ID in **Security events** and narrow or remove the matching custom rule for this API hostname. Do not use a browser-integrity or interactive-challenge rule on `/v1/*`;
- the connector endpoint is intentionally unauthenticated, so add an IP-based rate-limit rule for WebSocket handshake requests to `/api/extensions/ws`; do not use an interactive challenge for that path.

For defense in depth, create a Cloudflare Access self-hosted application for
the admin UI paths `/admin` and `/admin-assets/*`, restricted to administrator
identities. Do not apply an interactive Access policy to `/v1/*` or
`/api/extensions/ws`: backend clients and the Chrome connector cannot complete
an interactive login. The `X-Admin-Key` check remains mandatory even when the
dashboard is behind Access.

## 5. Deploy

Validate and deploy with:

```bash
bash scripts/deploy-production.sh
```

The helper:

1. validates Compose interpolation and required variables;
2. refreshes PostgreSQL and `cloudflared` images;
3. rebuilds the API from the checked-out repository revision;
4. starts PostgreSQL, API, and Tunnel in dependency order;
5. waits for the API container healthcheck.
6. verifies the deployed admin HTML, JavaScript, CSS, and an authenticated
   `GET /v1/api-clients` call from inside the API container.

The API image runs `alembic upgrade head` before starting Uvicorn, so schema migrations are applied on container startup.

Inspect the stack:

```bash
docker compose --env-file .env.production -f compose.production.yaml ps
docker compose --env-file .env.production -f compose.production.yaml logs -f api
docker compose --env-file .env.production -f compose.production.yaml logs -f cloudflared
```

## 6. Verify public health

Once the Tunnel route is active:

```bash
curl -fsS https://provider.example.com/health/live
curl -fsS https://provider.example.com/health/ready
```

Swagger remains available at:

```text
https://provider.example.com/docs
```

The administration dashboard is available at:

```text
https://provider.example.com/admin
```

Verify it without exposing the Admin Key on the command line by opening the
page in a browser and entering the secret when prompted.

If `/health/live` works inside Docker but not through the hostname, inspect the `cloudflared` logs and the Tunnel published application route before changing the API.

## 7. Connect the Chrome extension

Install the extension on a Chrome machine signed in to Google Flow. It automatically connects and reconnects to its configured Provider server; the packaged default is:

```text
Provider server: https://api.shopcongngheso5.io.vn
```

For a custom deployment, change the Provider server in the extension popup to your HTTPS hostname. There is no shared gateway credential to copy to each browser.

`/api/extensions/ws` is public by design. Anyone who can reach it can attempt to register a connector, so connector identity is not an authentication boundary. Use Cloudflare WAF/DDoS protection and an IP-based handshake rate limit to reduce abuse while preserving automatic extension connections.

After the extension connects, submit a real generation through the public API and poll its task until completion. The mock E2E suite is not a replacement for this live acceptance test.

`GET /v1/health` reports both `ready_accounts` and `video_lite_ready_accounts`. The latter is the number of connected accounts currently able to cover the 20-credit Lite-video minimum. If it is zero, video tasks remain queued and retry after `FLOW_PROVIDER_ACCOUNT_UNAVAILABLE_RETRY_SECONDS` instead of being failed immediately.

## 8. Database backups

Create a PostgreSQL custom-format dump before upgrades or risky maintenance:

```bash
bash scripts/backup-production-db.sh
```

Backups are written under `backups/`, are chmod `600`, and are ignored by Git. Copy important backups off the VPS as part of normal operations.

To inspect a dump:

```bash
pg_restore --list backups/flowprovider-YYYYMMDDTHHMMSSZ.dump | head
```

For a restore, stop API writes first, restore into PostgreSQL with `pg_restore`, then run the deployment helper again so the checked-out code and migrations are aligned. Test the restore procedure on a non-production database before depending on it for disaster recovery.

## 9. Updating production

Back up the database, fast-forward `main`, then redeploy:

```bash
bash scripts/backup-production-db.sh
git pull --ff-only origin main
bash scripts/deploy-production.sh
```

Review migration changes before deploying a revision that changes the database schema. Database backups are the rollback boundary for irreversible migrations.

## 10. Useful failure checks

```bash
# Compose and environment validation
docker compose --env-file .env.production -f compose.production.yaml config

# Container state
docker compose --env-file .env.production -f compose.production.yaml ps

# API startup/migration failures
docker compose --env-file .env.production -f compose.production.yaml logs --tail=200 api

# Tunnel connectivity/routing failures
docker compose --env-file .env.production -f compose.production.yaml logs --tail=200 cloudflared

# PostgreSQL readiness
docker compose --env-file .env.production -f compose.production.yaml exec -T postgres \
  pg_isready -U flowprovider -d flowprovider
```

Never expose PostgreSQL or the API container directly to the Internet as a workaround for a Tunnel configuration problem.
